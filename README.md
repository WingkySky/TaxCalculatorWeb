# 个税计算器 · 劳务报酬 / 工资薪金

一款专业的在线个税计算工具，支持两大所得类型：

- **平台连续劳务报酬**（如直播打赏、外卖配送、网约车等）——支持**旧政策生产经营所得**和**新政策累计预扣法**自动切换
- **工资薪金**——按累计预扣法计算社保公积金、专项附加扣除与个税，支持应发↔实发双向互算

两种类型均支持「多月累计」手工计算与「批量计算」表格上传。

## 功能特点

### 💰 所得类型切换
- 页面顶部一键切换「劳务报酬」/「工资薪金」，两个页签共用该选择
- 切换时自动联动说明文案、输入提示、断月开关显隐与批量列识别

### 🏙️ 城市社保公积金政策库（工资薪金）
- 内置 12 个主要城市（北上广深杭宁苏成渝汉西津）+ 自定义，**分险种**维护个人比例、**单位比例**与基数上下限（养老/医疗/失业/工伤/公积金各自独立；公积金单位比例缺省与个人同档）
- **政策数据源为 `tax-policy-data.json`**：线上访问（GitHub Pages 等）每次打开自动检查远端更新（版本号 `YYYY.MM`）；`tax-policy-data.js` 为自动生成的 file:// 双击离线兜底种子；数据文件缺失时仅保留"自定义"城市并提示
- **两层所有权 + 本机存档**：官方数据层（线上 JSON 自动更新 / file:// 由种子兜底）→ 本机浏览器存档（「政策库」页编辑/导入后即时保存，含官方基线快照）→ Excel / JSON 导出备份。官方推送更新时按字段**三方合并**：用户没改过的字段自动更新到官方新值，改过的字段保留用户值并标 ⟲（悬停见官方值，点击恢复官方值）；「自定义」与用户新增的城市/年度永不触碰；版本不前进则不回退。「恢复官方默认数据」一键还原（新增城市保留）；本机存档不跨浏览器/电脑，清除浏览器数据会丢失，跨机请导出 Excel/JSON；旧版本存档加载时缺失字段（如单位比例、工伤）自动按字段级补齐，不覆盖用户已改数值
- 多年度政策记录（含生效月区间，兼容广州/深圳 7 月~次年 6 月社保年度），按工资月份**自动匹配年度**，也可手动固定
- 公积金比例按城市可选档位（5%~12%）择档；**公积金月缴存额四舍五入取整到元**，社保保留到分
- 「政策库」页面：查看/编辑政策数据（含单位比例与工伤）、新增城市与年度、整库 **Excel 导入/导出**（扁平表格，含"单位比例(%)"列，兼容旧格式文件导入）与 JSON 导入/导出（程序化备份）；「工资参数」卡（内嵌于多月累计页）政策明细支持**预览月份切换**（计算按每笔发放月份自动匹配年度），并展示个人/单位实缴与企业用工总成本
- **溯源与核查状态（2026.10 起）**：每条年度记录可标 `status`（已核实/部分核实/待核实）、`checkedAt` 最近核查年月、`note` 口径备注与 `sources[]` 来源（标题/文号/链接/发布方/发文日期/确认内容/证实的险种）；「工资参数」卡政策明细带核查状态**轻徽标**，点击弹出该年度全部来源；「政策库」页可完整编辑，并按来源**逐险种派生"有据/无据"提示**（派生不覆盖人工声明的状态——贴了链接不等于已核实）。全库不虚标：无法核对即"待核实"，Excel 导入的数据一律"待核实"（Excel 不携带来源列）；旧 `pending` 字段读取时自动映射（true→待核实、false→部分核实），不再写出
- 数据已更新至 **2026 年度**（北京 36348/7270、上海 37731/7546、广深养老 27549 上限、江苏/重庆暂按 2025 标准执行等，更新于 2026-09-04）；广东最低工资自 2026-09-01 调整（广州 2680、深圳 2700，粤府函〔2026〕188号），广州公积金下限同步 2680，深圳失业保险下限/公积金下限同步 2700；广东省 2026 社保年度惯例 10 月公布，当前为沿用 2025 年度的过渡值
- ⚠️ 内置数值（含单位比例与工伤，按行业基准 0.2% 填写）均为参考值，请以当地社保部门公布为准；批量表格可带「城市」列（如 广州/深圳）按行内城市政策计算，也可整批选城市；无基数列时可勾选"按应发工资作基数"（自动按城市上下限 clamp）

### 🎁 年终奖（全年一次性奖金，工资薪金）
- 「多月累计」页签输入年终奖金额与发放月份，自动对比两种计税方案并推荐更优：
  - **单独计税**：奖金 ÷12 定档（月度税率表），应纳税额 = 奖金 × 税率 − 速算扣除数，每年限用一次
  - **并入综合所得**：奖金计入发放月累计收入正常预扣
- 批量模式新增「**年终奖**」列（表头：年终奖/全年一次性奖金/年度奖金等），按**人 × 年**自动对比择优；税后反算方向下并入对比不适用，一律按单独计税独立成行
- **无效区间避坑提示**：奖金落在 (36,000, 38,566.67]、(144,000, 160,500]、(300,000, 318,333.33]、(420,000, 447,500]、(660,000, 706,538.46]、(960,000, 1,120,000] 六段区间时多发反而到手更少，自动提示调整至区间下沿

### ➕ 专项附加扣除分项（工资薪金）
- 「工资参数」卡勾选「按项分列」后展开 7 项：**子女教育**（2,000/月/孩）、**3岁以下婴幼儿照护**（2,000/月/孩）、**继续教育**（学历 400/月；职业资格 3,600 元仅取得当月计入）、**住房贷款利息**（1,000/月，首套）、**住房租金**（1,500/1,100/800 按城市档，切换城市自动推荐）、**赡养老人**（独生 3,000；非独生分摊每人 ≤1,500 自动封顶）、**大病医疗**（年度，仅汇算提示）
- 政策校验：房贷与房租**互斥**（勾选自动取消另一项）；赡养分摊超限自动封顶并提示；大病医疗不参与月度预扣，结果区提示年度汇算清缴可申报金额（自付超 1.5 万部分，限额 8 万）
- 不勾选时沿用「单一总额（元/月）」模式；批量行内「专项附加扣除」总额列仍优先于全局分项

### 🏢 单位部分与企业用工总成本（工资薪金）
- 社保公积金同步计算**单位部分**（养老/医疗/失业/工伤/公积金，公积金单位缺省与个人同档）
- 结果表新增「社保公积金（单位）」列（悬停见分险种明细），汇总卡新增**企业用工总成本 = 应发工资 + 单位缴纳**；批量按人头同步展示
- 纯个人视角用户可忽略单位列，不影响原有计算

### 📊 导出 Excel（公式明细，工资薪金）
- 多月累计与批量结果均可导出 **xlsx 公式版**：常量列只有原始输入（应发、基数、比例、专项附加、年终奖），社保公积金、累计链、税率跳档、税额、企业总成本等派生值全部是**真实 Excel 公式**（如 `=ROUND(MAX(MIN(F2,27549),5510)*0.08,2)`，上下限与比例内联可溯源）
- 每格同时写入公式与缓存值：打开即显示数值，点开单元格可见计算来源，**修改任一输入自动重算全表**；换人/跨年/同月多笔的累计基准由导出器处理
- 原有 CSV 导出保留（CSV 无公式能力，需要溯源用 Excel 公式版）

### 🖨 打印/PDF 报告
- 三处结果区（多月累计劳务/工资、批量）一键打印**正式报告**，浏览器打印对话框内可「另存为 PDF」——`@media print` 样式 + `window.print()` 实现，零依赖
- 分节正式式版式：报告抬头（公司/部门名可定制，记忆上次输入）+ **一、计算参数 / 二、计算结果 / 三、备注** + 页脚免责声明
- 批量报告按人分节（工资条块：脱敏身份行 + 逐月小表 + 个人小计 + 总计），身份证/电话/银行卡**自动脱敏**（界面显示不受影响）
- 打印为 A4 白底黑字（不随亮暗主题），表头跨页重复，逐人块不跨页撕裂；数据直接读现有结果，计算引擎零改动

### 🧾 年度汇算清缴
- 侧栏「计算」组独立页面：全年综合所得合并计税，与已预扣税额比较得出**应退/应补**（绿/橙区分）
- 收入范围：工资薪金与劳务报酬按月输入（12 格网格，可一键**带入多月累计页当前结果**）；稿酬、特许权使用费按年度总额输入（收入额分别按 ×80%×70%、×80% 折算）
- 预扣税额：留空由工具估算（工资/劳务复用累计预扣引擎、与本工具月度口径一致；稿酬/特许权按法定 20%），填入实际值则按「手填」计并在结果中标注
- 专项附加扣除按**年度口径**独立 7 项输入（默认 0，placeholder 提示国家标准：子女/婴幼儿 24,000、继续教育 4,800 或职业资格 3,600、房贷 12,000、租金 18,000/13,200/9,600、赡养 36,000 或分摊 ≤18,000/人、大病医疗据实 ≤80,000）
- 政策提示：补税 ≤400 元或综合所得年收入 ≤12 万（依法预扣预缴）可免于办理汇算；年度税率表与月度预扣共用同一张（避免口径漂移）

## 政策数据维护

政策数据（城市社保公积金基数与比例）的唯一维护入口是仓库根目录的 **`tax-policy-data.json`**：

1. 编辑 JSON（根结构：`version` 版本号 `YYYY.MM` + `cities` 城市表）。年度记录可带**溯源字段**：`status`（`confirmed` 全部险种有官方依据 / `partial` 部分有据 / `unverified` 无从核对；缺省 unverified）、`checkedAt` 最近人工核查年月（YYYY-MM）、`note` 口径备注、`sources[]` 来源记录（每条 `title` 必填，`ref` 文号 / `url` / `publisher` / `date` / `confirms` 确认了什么 可选，`covers` 声明证实哪些险种、缺省全项）；旧 `pending` 字段不再写出（读取时 true→unverified、false→partial）；
2. 运行 `node tools/build-policy-seed.js` 重新生成 file:// 兜底种子 `tax-policy-data.js`（`--check` 仅校验两者一致）；
3. 提交并推送。GitHub Pages 自动重新部署，所有用户下次打开页面即收到更新。

远端更新到达时按「字段级三方合并」写入用户浏览器：官方新值只覆盖用户未改动的字段；用户改过的字段保留并在政策库页标 ⟲，可一键恢复官方值；来源列表按条目身份（文号→链接→标题）三方合并，同键冲突以官方为准；自定义/新增城市与年度永不触碰；远端版本不高于本机已知官方版本时跳过（不回退）。版本号建议用数据生效年月（如 `2026.10`）。所有数值均为参考值，请以当地社保部门公布为准。

## 计税规则

### 劳务报酬（平台连续劳务）

**政策切换**：
- **2025年10月1日及之后**：适用新政策（连续劳务，累计预扣法）
- **2025年9月及之前**：适用旧政策（生产经营所得，不扣税）

**新政策：累计预扣法**（依据国家税务总局公告2018年第61号）：

| 累计应纳税所得额 | 税率 | 速算扣除数 |
|---------------|------|----------|
| ≤36,000 | 3% | 0 |
| ≤144,000 | 10% | 2,520 |
| ≤300,000 | 20% | 16,920 |
| ≤420,000 | 25% | 31,920 |
| ≤660,000 | 30% | 52,920 |
| ≤960,000 | 35% | 85,920 |
| >960,000 | 45% | 181,920 |

- **预扣收入额** = 每次劳务报酬收入 × 80%
- **累计预扣税额** = (累计预扣收入额 - 累计减除费用) × 适用税率 - 速算扣除数
- **累计减除费用** = 5,000元/月 × 累计月份数

### 工资薪金（累计预扣法）

依据国家税务总局公告2020年第13号，税率表与上表相同：

- **累计应纳税所得额** = 累计应发工资 − 5,000×月份数 − 累计社保公积金（个人部分） − 累计专项附加扣除
- **本期预扣税额** = 累计应纳税额 − 累计已预扣（为负时取 0）
- **实发工资** = 应发工资 − 个人社保公积金 − 个人所得税

**社保公积金（个人部分，按城市政策分险种计算）**：

社保公积金 = Σ [ clamp(社保基数, 该险种城市下限, 该险种城市上限) × 该险种个人比例 ]

- 内置城市政策库维护各险种的个人比例、单位比例与基数上下限（如广东养老/失业按全省口径、医疗单独设限、公积金另有口径；工伤仅单位缴纳）
- 公积金基数默认跟随社保基数，可单独设置；比例按城市可选档位（5%~12%）择档
- 批量表格中社保公积金一律按基数自动计算：行内基数列 > 全局基数 > 应发工资作基数（勾选后）> 0 并标注；公积金比例按 行内「公积金比例」列（填 5 = 5%，兼容 0.05/"5%"）> 「工资参数」择档；城市按 行内「城市」列 > 批量页「整批参保城市」 > 「工资参数」城市

**年终奖（全年一次性奖金）**：

- 单独计税：应纳税额 = 奖金 × 按奖金÷12 确定的月度税率 − 速算扣除数（税率 3%~45% 七档，速算扣除数 0/210/1,410/2,660/4,410/7,160/15,160）
- 并入综合所得：奖金计入发放月累计收入，正常参与累计预扣
- 每人每年只能使用一次单独计税；系统按人按年自动对比并推荐更优方案

**示例**：月薪 10,000，自定义城市（养老 8%+医疗 2%+失业 0.5%+公积金 12%，无上下限），专项附加 1,000/月 →
社保公积金 2,250；1月个税 = (10,000 − 5,000 − 2,250 − 1,000) × 3% = **52.50**；实发 = **7,697.50**
若参保广州（失业 0.2%、公积金 5% 档），同样月薪社保公积金为 1,520，个税与实发随之不同——这正是分城市政策的意义
年终奖示例：36,000 单独计税 = 36,000 × 3% = **1,080**；若并入综合所得（月薪 1 万×12、社保公积金 2,250、附加 1,000）税负增量为 2,550 → 推荐单独计税，节税 1,470

### 通用规则
- **跨年重置**：每年1月起，累计收入、累计已预扣税额、累计减除费用均归零重新起算
- **断月重置**（仅劳务）：开启后，相邻月份如果中断超过1个月，累计自动归零重新起算
- **同月多笔**：同一月份多笔收入合并计税，当月减除费用与社保公积金只计一次

## 界面与架构

- **侧边栏控制台布局**（Ant Design 企业蓝设计语言，手写 CSS 实现，零依赖）：计算（多月累计 / 批量计算 / 年度汇算）、配置（政策库）、帮助（计算规则）五个独立页面，hash 路由可直达（如 `index.html#/annual`）；「工资参数」以内嵌卡形式置于多月累计页顶部（仅工资薪金模式显示，可折叠并记忆状态），旧链接 `#/params` 自动落回多月页
- **亮暗双主题**：默认跟随系统 `prefers-color-scheme`，顶栏一键切换并记忆；全部颜色收敛为 CSS 变量（`css/tokens.css` 两套 token）
- **纯静态多文件架构**：样式（`css/`）与逻辑（`js/`）按模块拆分，各模块以 IIFE 命名空间暴露接口（`TaxEngine` / `PolicyLib` / `SocialIns` / `Exporter` / `PageShared` / `PageMulti` / `PageParams` / `PagePolicy` / `PageRules` / `App` 等），引入顺序即依赖顺序；计算逻辑与 UI 彻底分离。批量计算内部按性质五分——`BatchParse`（解析与智能识别，纯逻辑）/ `BatchCalc`（单人计税流水线，纯逻辑）/ `BatchSource`（多文件源状态）/ `BatchView`（渲染与 UI 事件）/ `BatchExport`（导出），由 `PageBatch` 门面聚合为单一命名空间，外部引用零感知
- 内置八套件控制台自检（**288 项断言**，`TaxTest.runAll()` 页面加载时自动运行，console 查看）；命令行 `node tests/run.js` 可秒级回归同一份断言（零依赖，无需浏览器，任一失败退出码 1）

## 使用技术

- 纯前端实现，无需后端服务、无构建步骤、无 npm 依赖
- 支持 SheetJS (xlsx) 库处理 Excel 文件：**本地优先**——优先加载与页面同目录的 `xlsx.full.min.js`（file:// 双击离线可用），缺失时回退 CDN（同一版本 0.20.1），两者都不可达时提示
- 响应式设计：桌面侧边栏可折叠，≤768px 自动转抽屉菜单，适配桌面和移动端

## 本地使用

直接在浏览器中打开 `index.html` 文件即可使用，无需安装任何依赖。

> 跨机拷贝或分发时，请将 `index.html` 与 `css/`、`js/` 目录和 `tax-policy-data.js`（城市政策初始化数据）、`xlsx.full.min.js`（Excel 功能本地库，缺失时回退 CDN）放在同一目录整体拷贝；缺少 `tax-policy-data.js` 时工具仍可用（仅"自定义"城市），并会提示导入 Excel/JSON 政策数据。
>
> 挂网部署：将整个目录上传到任意静态服务器即可，无需任何构建。
