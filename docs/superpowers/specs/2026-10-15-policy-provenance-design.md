## 0. 背景与子项目定位

参考 city-salary 的政策维护经验（逐城来源档案、核查节奏日历、诚实性纪律、CI 门禁），结合本仓库「JSON 唯一数据源、file:// 双击可用、纯静态多文件」的架构约束，政策库能力升级拆为四个子项目，按依赖顺序推进：

| 步骤 | 内容 | 与本份关系 |
|---|---|---|
| ① 溯源与状态分级 | 来源/状态进数据层（本文档） | 本份 |
| ② 覆盖面 | city-salary 337 城数据转换导入（MIT 需署名），来源随转换一并带入 | 后续，依赖① |
| ③ 核查日历+过期门禁 | 1月查医保/7月查基数的日历 + 到期报红检查，回归门进 GitHub Actions | 后续，依赖① |
| ④ 半自动核查工具 | 维护者侧核查简报生成 | 最后，依赖①③ |

本仓库现状痛点：政策数据无任何来源/文号/链接/更新日期字段，质量标记仅一个 `pending` 布尔；用户无法溯源，维护者无法为数据背书。

| 决策点 | 结论（用户确认） |
|---|---|
| 本期目标 | 可信度、覆盖面、新鲜度、核查效率四项全要，拆四步分批做 |
| 先做 | 子项目①溯源 schema 基建 |
| 来源存储位置 | 方案A：全部内联 `tax-policy-data.json`（B 并行档案文件、C 折中被否——两处事实源需额外防漂移，file:// 展示还要二次打包） |
| 溯源可见性 | 政策库页完整维护 + 前台轻徽标（前台全量展示被否） |

## 1. 数据层（schema）

`tax-policy-data.json` 的 `version` 升为 `"2026.10"`。年度记录新增四个**可选**字段，险种 `items` 结构一字不动：

```jsonc
{
  "label": "2026 社保年度",
  "effective": ["2026-07", "2027-06"],
  "status": "confirmed",          // 见状态词汇表
  "checkedAt": "2026-10",         // 最近一次人工核查年月 "YYYY-MM"，可选
  "note": "工伤按0.2%基准费率简化，实际按单位行业档次",
  "sources": [{
    "title": "关于2026年度各项社会保险缴费工资基数上下限的通告", // 必填
    "ref": "京人社发〔2026〕X号",       // 文号，可选
    "url": "https://…",                // 可选
    "publisher": "北京市人力资源和社会保障局", // 可选
    "date": "2026-07-02",              // 发文日期，可选
    "covers": ["pension", "medical"],  // 该文件证实哪些险种；缺省=五险全项
    "confirms": "上限=12183×3，下限6821" // 它确认了什么，可选
  }],
  "items": { /* pension/medical/unemployment/injury/fund，不变 */ }
}
```

状态词汇表：

| status | 含义 | 徽标 |
|---|---|---|
| `confirmed` | 全部险种数值有官方文件（或官方渠道互洽双源）证实 | 绿「已核实 ✓」 |
| `partial` | 部分险种有官方依据，其余为推断或第三方来源 | 黄「部分核实」 |
| `unverified` | 无从核对 | 灰「待核实」 |

规则：

1. **缺省即 unverified**：加载时无 `status` 的年度记录（含旧存档）按 `unverified` 处理。
2. **险种级依据是派生的，不存储**：任一 source 的 `covers` 含某险种 → 该险种「有据」，否则「无据」。派生结果**不覆盖人工声明的 status**（贴链接≠数值已核实）。
3. **加载宽容校验**（与现有 mergeLibrary 宽容风格一致）：缺 `title` 的 source 条目丢弃；`covers` 非法键忽略；`status`/`checkedAt` 格式非法回落缺省。坏数据降级显示，绝不崩计算。
4. **`pending` 停止写出**，读取时一次性映射：`pending:true → unverified`、`pending:false → partial`（当初手工核对过、README 有文号，但未存完整来源记录，不能自称 confirmed）。
5. **诚实迁移**：存量 13 城 27 条按规则 4 补 `status`；README 中现成文号（如粤府函〔2026〕188号）填入对应 `sources`，只搬运已有信息，不新做核查（核查是子项目③④的事）。

## 2. 合并与同步管道

- `compareVersions` 不变（version 仍整库一个）。
- **三方合并扩展**（mergeLibrary）：
  - `status`/`checkedAt`/`note`：标量，走与数值字段相同的三方规则（本地未动保本地，远端更新收远端）。
  - `sources[]`：按条目身份键做三方 diff——身份键依次取 `ref` → `url` → `title`（归一化 trim 后非空者）。本地新增保留、远端新增吸收、同键双方都改→远端官方赢（与现有数值防回退原则一致）。
  - `applyRemoteOfficial` 防回退同样覆盖新字段：远端 version 更新时官方字段全收。
- **Excel 政策表**：导出加「核查状态」「最近核查」两列（中文状态文案），来源不进 Excel；导入的数据一律 `status:"unverified"`、`sources:[]`——没来源不冒充有。JSON 导入导出原样带全部字段。
- **种子生成**：`tools/build-policy-seed.js` 逻辑不改（全量序列化，新字段自动随种子走），`--check` 自动覆盖新字段；改完 JSON 必须重生成种子并过 `--check`。

## 3. UI

### 3.1 政策库页（page-policy.js，维护者完整视图）

- 城市-年度选择旁状态徽标：绿「已核实 ✓」/ 黄「部分核实」/ 灰「待核实」。
- 编辑器新增「来源与核查」卡片：状态下拉（三档）、`checkedAt` 月份输入、`note` 文本域、来源列表编辑（每条：标题/文号/链接/发布方/发文日期/确认内容 + `covers` 五险种多选，可增删）。
- 卡片底部派生提示行：逐险种标注「有据/无据」，如「工伤：暂无来源支撑」，把没依据的险种顶到眼前，方便逐项补证。

### 3.2 前台（page-params.js 单月计算器，普通用户轻徽标）

- 社保公积金明细卡标题行右侧小徽标，文案 = `{yearKey}年度 · 已核实 ✓ / 部分核实 / 待核实`（直接用年度键，不解析各城不一的 label）。
- 数据通道：`PolicyLib.resolvePolicy` 返回值扩展，透传所匹配年度记录的 `status`/`sources`/`note`/`checkedAt`（浅拷贝，防消费方篡改库数据）；不新增第二解析路径。
- 点击徽标弹浮层：年度 label、状态、来源列表（文号+发布方+日期+确认内容，`url` 可点）、固定尾注「政策数据仅供参考，以当地社保部门公布为准」。
- `custom` 自定义城市不出徽标（无来源可展示，避免噪音）；字段缺失/加载异常时徽标整体不渲染——前台永不因政策数据残缺报错。

## 4. 迁移、测试与验收

### 4.1 迁移（一次性）

1. 一次性脚本按 §1 规则 4 给 13 城 27 条补 `status`；README 现成文号搬入 `sources`。
2. `version` 升 `"2026.10"`，重生成种子，`--check` 通过。
3. 用户旧 localStorage 存档：加载时按同规则映射 `pending`，不回写旧字段。

### 4.2 测试（self-tests.js 扩展，进现有回归门）

1. schema 缺省与宽容校验：无 status → unverified；缺 title 丢弃；坏 covers 忽略；非法 status 回落。
2. 三方合并含 sources：本地增/远端增/同键冲突远端赢 三方向断言。
3. 旧数据 `pending` 映射两方向。
4. JSON 导出→导入 roundtrip 保新字段。
5. Excel 导入 → 强制 unverified + 空 sources；Excel 导出含「核查状态」「最近核查」两列。
6. `resolvePolicy` 透传溯源字段且为浅拷贝；custom 城市无徽标字段。
7. 徽标渲染（DOM 桩）：三档状态 + 缺字段不渲染不报错。
8. 既有 225 项回归门全绿；`build-policy-seed.js --check` 通过。

### 4.3 验收

- 回归门全绿 + 种子 `--check` 通过 + file:// 双击冒烟（徽标渲染、浮层、编辑器新卡片可用）。
- 全库无虚标：抽查任一 confirmed 记录必有至少一条 source 覆盖全部险种。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| sources 撑大 JSON（337 城时约 +数百 KB） | 子项目②统一解决加载策略；本期 13 城增量 2-4 KB 可忽略 |
| 前台徽标误导（贴了链接就显绿） | 派生「有据」不覆盖人工 status；徽标文案区分三档 |
| 用户本地补录来源与远端官方更新冲突 | sources 按条目身份三方合并，同键冲突远端赢 |
| 旧 localStorage 存档不兼容 | pending 读取映射；新字段全部可选，旧结构照常工作 |
| Excel 交换丢溯源 | 有意为之：Excel 只走数值，导入即 unverified，诚实降级 |
