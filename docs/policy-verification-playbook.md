# 政策数据核查手册（playbook）

> 本手册回答一个问题：**怎么为 `tax-policy-data.json` 找到官方依据、怎么确认数字是真的、查不到时怎么办。**
> 面向对象是几个月后的自己，以及执行核查的 AI 代理——那时不会记得「为什么上海医保费率要单独盯」。
>
> 方法论改编自 [weante/city-salary](https://github.com/weante/city-salary)（MIT）的核查体系，
> 该项目用这套流程完成了 337 城逐城溯源（56+ 批核查、968 条官方 URL），经过大规模实战检验。

## 〇、三条铁律（先于一切）

1. **绝不编造数字。** 查不到就如实标 `unverified` 并在 note 写明暂用口径——宁可「待核实」，不给看起来合理的假值。
2. **「被限流」≠「确实没有」。** 搜索/抓取失败必须带 `[RATE-LIMITED]` / `[FETCH-FAILED]` 标记记录，与「已确认未找到」严格分开——假的"未找到"比不核查更糟，因为它看起来像已核查。
3. **未证实 ≠ 已确认错误。** 任何来源（包括 AI 代理）报出的"不一致"，未经本人抓原文核对，一律不改值。city-salary 实测：134 条代理报出的 mismatch 只有 18 条（13%）是真的。

## 一、什么时候核查（三个检查点）

不同险种调整周期不同，只设一个检查点会漏检：

| 检查点 | 核查范围 | 覆盖城市 |
|---|---|---|
| **每年 01-01** | 医保/生育基数与费率（自然年调整）；公积金按自然年城市的基数 | 杭州/南京/苏州/成都/武汉/西安/天津 的基数；广州/深圳的**医保**（两城医保按自然年、其余按社保年度，见数据 label） |
| **每年 07-15** | 养老/失业/工伤基数与公积金年度基数（社保年度 7 月起执行） | 北京/上海/广州/深圳/重庆（2026 年度均 2026-07 起）；京沪津渝五险同口径 |
| **限期费率文件到期次日** | 该费率是延续、调整还是恢复原值 | 见「待复核线索」；**这是最易漏检的一类**——到期日常落在两个年度检查点之间（city-salary 栽过：伊犁降费期到期 19 个月无人发现） |

每次核查后：更新对应记录的 `checkedAt` 与 `status`，`version` 升一个级（建议 `YYYY.MM`），重生成种子、跑回归门、提交推送。

**运营节奏（机制自我执行，不靠记性）**：

- **每次提交**：GitHub Actions（`.github/workflows/ci.yml`）在 Node 18/20/22 三版本矩阵自动跑三道守卫——种子一致性（`build-policy-seed.js --check`）→ **政策时效门禁**（`node tools/policy-expiry.js`：每城现行期覆盖、限期费率到期、confirmed 必须有全险种来源支撑、旧 pending 残留，四道门）→ 回归门（`node tests/run.js` 八套件）。
- **每月**：本地跑一遍 `node tools/policy-expiry.js`，看 60 天内到期提醒，提前安排核查，别等到期。
- **每季**：看门禁输出的 status 分布——**unverified 数应单调下降**，上升要能解释。
- **随时（限期费率）**：文件到期次日触发专项核查。已到期但暂无法核实的，在 `tools/policy-expiry.js` 的 `ACKNOWLEDGED` 登记处置（`{ date, reason }`）才不红——**逼你做一个有记录的判断，而不是默默沿用**；核实后更新数据并清除登记。

## 二、四关复核（改值的门槛）

任一关不过，**不改值、不升 status**，能记 warn 就记（我们的等价物：保持 `unverified`/`partial` + note 写明卡在哪一关）：

| 关 | 问什么 | 典型陷阱 |
|---|---|---|
| **① 口径** | 是「企业职工」口径吗？ | 机关事业单位、居民、灵活就业口径数值不同；**标题才是准的**——按页面结构特征猜口径翻过车（来宾：机关条目被误判为企业口径） |
| **② 生效** | 该文件现行有效吗？ | 征求意见稿（草案）≠ 现行；阶段性降费文件早已到期仍挂在检索结果里（南宁 2019 年降费件）；**警惕「调整前」数值**——city-salary 的安庆数据就是抄了通知里"调整前上限"那句话 |
| **③ 数字互洽** | 同一件文件里的数能互相印证吗？ | 见下方「算式自校验速查」；自校验必须用**同一件文件里的两个数**，用从目标反推的年均工资当推手等于没校验（24276÷3 非整数 → 上限方向自校验不成立，只能缴存额方向自洽） |
| **④ 来源** | 发布方是官方吗？ | 见下方「来源判定」 |

## 三、算式自校验速查

| 数值 | 常见构成 | 校验式 |
|---|---|---|
| 养老/失业基数上限 | 全口径城镇单位就业人员月均工资 × 3 | 上限 ÷ 3 应为整数或接近整数 |
| 养老/失业基数下限 | 月均工资 × 60%（多数省）或最低工资 | 下限 ÷ 0.6 同上 |
| 医保基数 | 各市自定：60%~80% 起（如雅安按全市 80%、贵州分市 60%~80%） | 先确认本市口径比例再验算 |
| 公积金基数上限 | 上年度月均工资 × 3 | 同上 |
| 公积金基数下限 | 本市最低工资标准（多档城市分档） | 对照人社厅最低工资文件 |
| 公积金月缴存额上限 | 基数上限 × 12% × 2（单位+个人） | 上限×0.12×2 对照原文；**取整方向因城市甚至因文件而异**（有向下取整、半进位向上、四舍五入），校验不成别当数据错 |
| 大额医疗补助 | 常见固定额（如 15 元/月 = 180 元/年） | 年额 ÷ 12 对照 |

## 四、来源判定

- **算官方**：`.gov.cn` 域名；或经确认的政府/事业单位官网——公积金中心多为独立事业单位，官网普遍用 `.com/.cn`（如各地 `zfgjj`/`gjj` 域名），须核实归属后采用。
- **排除**：商业聚合站、媒体转载、个人博客、百科（本地宝/知乎/新浪/腾讯新闻/southmoney 等）。
- **DNS 存在 + HTTP 200 不证明官方**：city-salary 累计遇到 7 例公积金域名被抢注（`www.hngjj.cn` 是德甲直播站、`www.glgjj.cn` 是色情站）——必须抓正文核对 `<title>` 与 ICP 备案号。
- **二手源的三个指纹**：① 算术错误（声称 4986 = 8433×0.6，实际 5059.8）；② 同站两表互相矛盾；③ 引用的文号查无此文。命中任一即弃用。
- **"多个独立来源"很可能同源**（都抄同一篇通稿）——数来源个数没用，拿到官方原文才算数。

## 五、取数：tools/policy-research.js

```bash
node tools/policy-research.js search "查询词"   # 搜索+抓第一个政府页+抽候选
node tools/policy-research.js gov    "查询词"   # 只列政府域名结果
node tools/policy-research.js fetch  <url>      # 抓正文
node tools/policy-research.js facts  <url>      # 抓正文并抽取上下限/文号/费率候选
```

链路（2026-10-16 实测，详见工具头注释）：搜索走 **必应中国 → Brave → DDG Lite** 降级链（大陆网络下 Brave/DDG 直连超时，必应中国可用）；抓页走 **直连 → Jina Reader → 本机 Edge 无头** 降级链（国内政府站直连 200 且最快，Jina 救挑战页，Edge 救 SPA/强反爬）。

**已知边界与对策**：
- **必应中国对多概念查询会劣化成「只搜首词」**（实测「上海 职工医保 费率」返回的全是上海旅游页、回显搜索词却完整）。对策：① 用紧凑词组（「北京社保」式）多次单概念查询；② 换词序让最关键的词在前；③ 直接走政府站内检索（各政府门户有站内搜索接口，如开封 `POST /search5/search/s`）；
- **国际搜索引擎（Brave/DDG）在本机网络直连超时**，保留在降级链里是为换网络环境后可用；
- **gov 站内检索的富矿**：电子税务局税费知识库（各市医保费率逐条收录，纯 SPA 必须 Edge 渲染，条目 ID 只能靠外部搜索获得）。

**限流纪律（务必遵守）**：
- 并发核查任务压到 **2~3 个**；请求间隔 **≥10 秒**（city-salary 开 6 个并发直接把 Brave 打到 429、Jina 打到连不上）；
- 工具已内置退避重试（0→15→45 秒），但退避只是止损，主动限流才不浪费窗口；
- 见到 `[RATE-LIMITED]` / `[FETCH-FAILED]` 等几分钟再试；**报告里必须单列「因限流未能核查」一节**，与「已确认未找到」分开。

**工具哲学：机器只取数与摘录，不做采纳判断。** `facts` 抽出的是候选（同句最大/最小数、文号、费率），政策原文里「暂按」「待发布」「不含生育」「调整前」这类限定语机器识别不了，采纳与否由人（或四关复核）决定。实测：对未写基数数值的文件诚实返回 null，不硬凑。

## 六、抓取技巧（实战积累，别重蹈覆辙）

- **县级政府网站往往比省级厅局好抓**：省厅栏目页可能只有几百字符，而县级/市级转载页有全文。省级抓不到时，先搜「该通知 + 某县/某市」。
- **政策库的「上一篇/下一篇」是发现文号的捷径**：相邻条目常直接暴露同批文号。
- **电子税务局税费知识库是医保费率富矿**，但纯 SPA——Jina 只拿到外壳，必须 Edge 渲染（`--virtual-time-budget` 调大到 20 秒级）；没有 URL 检索入口，只能靠外部搜索拿条目 ID；**取数后必须核对条目标题的口径**（企业/机关条目在同库并存）。
- **折叠面板内容抓不到**（不在初始 DOM 里，headless `--dump-dom` 不能交互）——需要时用 CDP 模拟点击。
- **正文可能是 PDF 或扫描件**：静态 HTML 很短但正文是 PDF 时用无头浏览器+PDF 解析；扫描 PNG 用 Windows OCR（中文字体无 ToUnicode 映射的 PDF 同理按图读）。
- **记 URL，不能只记文号**（city-salary 血的教训：7 份旧文档零链接，重新核查只能从零搜索，而搜索恰是最易被限流的一环）。优先记 `.gov.cn` 原文页，不记转载页。

## 七、更新数据的标准流程

1. **查**：`policy-research.js` 取数（限流纪律照守）；
2. **四关复核**：全过才动数值；不过则保持/降级 status 并在 note 记录卡点；
3. **改 `tax-policy-data.json`**：数值 + `status`/`checkedAt`/`sources[]`（title 必填，ref/url/publisher/date/confirms/covers 尽量齐全，**URL 必须记**）；
4. `node tools/build-policy-seed.js` 重生成种子（`--check` 必过）；
5. `node tests/run.js` 回归门全绿（新增数值最好配抽查断言）；
6. README「数据已更新至…」段落与 version 涟漪；
7. 提交推送，**打开线上页面核验**徽标与新数值渲染。

## 八、不可用路径（已证实，勿浪费时间重试）

| 路径 | 状况 |
|---|---|
| Brave / DDG（本机网络） | 国际直连超时（curl 000）——换网络环境后降级链自动启用 |
| 必应中国多概念查询 | 劣化为「只搜首词」（见第五节对策），单紧凑词组可用 |
| 百度 | 弹安全验证 |
| Bing 国际版 RSS | 查询被截断 |
| 搜狗 | 返回多为图片/新闻 |
| Jina 带浏览器 UA | 返回 Cloudflare 挑战页（工具已处理，勿改） |
| 微信公众号正文（mp.weixin.qq.com） | 常抓取受阻，仅作线索不作来源 |
